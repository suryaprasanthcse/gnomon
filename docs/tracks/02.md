# Track 02 · Memory and coordination for many agents

GNOMON enters Track 02. The shared memory is one FalkorDB graph per tenant whose every change is a logged, hash-chained
rewrite, so agents share state, hand work to each other and recover from crashes without a side channel.
Sections refer to `docs/design/master.md`; proofs are the rows of its section 26, run by `scripts/demo_proofs.sh`.

| Focus area | How GNOMON meets it | Where | Proof |
|---|---|---|---|
| Episodic memory | The rewrite log: every applied change is a `Rewrite` with agent, rule sha, parameters, read position and previous hash (`CAUSED_BY` links causes) | `gnomon/kernel/`, `gnomon/rules/core/` | Proof P4, Proof P5 |
| Semantic memory | Bitemporal facts: every relationship carries valid time `[vf, vt)` and transaction time `[ts, te)`; supersede, end and void keep what was once believed | `gnomon/rules/families/` | Proof P4, Proof F |
| Procedural memory | Rule templates are pinned by sha and registered by a logged rewrite; an agent can only invoke a rule that is active under that sha | `gnomon/rules/registry.yaml`, `gnomon/kernel/registry.py` | Proof P1 |
| Shared state and handoffs | Task leases (`ClaimTask`, `Handoff`, `ExpireLease`, `CompleteTask`); optimistic concurrency by view keys, so a stale proposal is `REJECTED_STALE` and names the key that moved | `gnomon/footprint/`, `gnomon/rules/core/` | Proof P2, Proof P3 |
| High-concurrency reads and writes | Writes to one graph are serialized by FalkorDB and the first committer wins: 50 simultaneous claims give one `APPLIED` and 49 `REJECTED_GUARD`; reads go through `GRAPH.RO_QUERY` (and replicas in a larger deployment) | `gnomon/kernel/service.py`, `gnomon/query/` | Proof P1, Proof G |
| Separate memory per tenant | One graph per tenant (`t:<tenant>`); tenants share nothing except typed, ordered messages over a channel (federation) | `gnomon/federation/` | Proof D |

**What a judge can run.** `scripts/demo_proofs.sh P1 P2 P3 D G`. Proof P3 kills an agent mid-lease: the lease
expires, another agent continues, the replayed proposal returns `DUPLICATE` and the outbox delivers once. Proof D fans a
health change out to two tenants, orders it in the federated log, quarantines a sender with a skewed clock and
shows K9 green. Proof G injects three corruptions and shows the predicted audit checks catching them.

**Known limit most relevant here.** One writer per graph (sec 28, item 6): throughput is bounded per tenant and scales
by adding tenants.
