# Track 03 · Knowledge that stays current and can be traced to its sources

GNOMON enters Track 03. Every answer an agent gets from the graph carries the ids of the facts behind it, every change
carries the rewrite that made it, and a changed fact makes anything that relied on it stale.
Sections refer to `docs/design/master.md`; proofs are the rows of its section 26, run by `scripts/demo_proofs.sh`.

| Focus area | How GNOMON meets it | Where | Proof |
|---|---|---|---|
| Knowledge from docs, tickets and chats | Alerts, health reports and receipts enter as `Event` nodes (`Observe.alert`, `Observe.health`, `Observe.receipt`); agents write `Message` nodes and cross-tenant notices | `gnomon/rules/core/`, `gnomon/federation/messages.py` | Proof P2, Proof D |
| Ownership and expertise | `OWNED_BY` history for services, `MEMBER_OF` for agents, `HAS_SKILL` for task routing, answered at any past time by queries Q1 to Q4 | `gnomon/query/reads/` | Proof P4 |
| Tracing decisions to their sources | `CITES` edges, `Evidence` paths, `CAUSED_BY` between rewrites, and the federated `why`, which follows a cause across tenants | `gnomon/audit/runner.py`, MCP `why` | Proof P4, Proof B |
| Keeping knowledge current | Supersede, end and void keep history; projections (`OWNER_NOW`, `DEP_NOW`) are derived; a fact that moved after an agent read it makes its proposal `REJECTED_STALE`, naming the key, the sequence and the rewrite | `gnomon/footprint/`, `gnomon/rules/families/` | Proof P2 |
| Answers with clear sources | Every binding read returns the `fid` of each fact used; `ProposeCause` and `PostUpdate` require citations that are still live at commit time | `gnomon/mcp/tools.py`, `gnomon/rules/core/` | Proof P2, Proof P4 |

**What a judge can run.** `scripts/demo_proofs.sh P2 P4 P5 F`. Proof P2 shows an invented id refused by id provenance
and a stale proposal refused after an ownership retraction. Proof P4 shows `why` across four agents and the same
service read as Q1 (valid time), Q2 (current belief) and Q3 (past belief). Proof P5 shows a replay into a fresh graph
giving an equal state hash, and an out-of-band edit caught by K4 with the property named. Proof F answers "what would we
have done then" from the log.

**Known limit most relevant here.** `known_at_pt` has millisecond precision and node properties are current-only
(sec 28, items 8 and 9): use the sequence-based predicates for exact questions about the past.
