## Risky decisions

1. **A third platform bug, worked around in R11 (S25, D-25).** On the pinned image, §9.12's `OPTIONAL MATCH (i)-[rc:ROOT_CAUSE]->() WHERE rc.te = $INF …` after the AFFECTS match and the task aggregation never sees the root cause. EXPLAIN shows the filter pushed under the optional traverse, before `rc` is bound, so ResolveIncident could never apply. R11 now counts current root causes with `sum(CASE …)`, which means the same. The other optional-with-WHERE shapes (ClaimTask's lease check, OpenIncident's open duplicate, ProposeCause's current cause and cites) are covered by passing guard tests. Any new body that filters an OPTIONAL MATCH after an aggregation needs a guard test.
2. **Probe naming and granularity.** §9's preamble says "one probe per WHERE conjunct, G1…Gn", while the rule sections name grouped probes (`ttl_bounds`, `holder_live_lease`). I generated one probe per guard point: each plain MATCH and each top-level WHERE conjunct, skipping a WHERE that only filters an OPTIONAL MATCH. Names are `G<k>:<label>`, and the labels live in `registry.yaml`. Diagnosis is therefore finer than the spec's grouped names, e.g. `G4:ttl_positive` and `G5:ttl_max` instead of `G3 ttl_bounds`. Probes rebuild `now` from Head (`max(pt, wall)` live, `$rec_pt` otherwise), so a probe for a rule that compares against `now` can disagree with the apply by the milliseconds between them; diagnosis then reports INDETERMINATE.
3. **The lints were refined for these rules (D-22).**
   - Untyped cite relationships read any fact type (`*`). Without that, R2.OWNED_BY × R9 would be classified "commutes".
   - A creation under a `{pid}`-only key counts as fresh, because P0 refuses a known pid. Without that, L1 would refuse R9's Outbox row.
   - L3's one-row check now counts only named nodes and treats `WITH DISTINCT` as collapsing. It leaves parallel edges to the guards (I6), which means L3 would not catch a body that relies on an invariant that fails.

   Other A06 decisions: D-23 (A05's dynamic verification extended to the new rules), D-24 (shared rule-test world in `tests/support/ir_world.py`), D-26 (two A04 registry-size assertions retargeted).

## Questions

Answer each question in your own words (rule 12). Then set the last line to `HUMAN-SIGNED: yes`.

### Q1. Why does ExpireLease compare against now rather than a parameter?

Answer (human): Lease expiry must be governed authoritatively by the kernel's transaction timestamp ($now / HLC), not by arbitrary client-supplied parameters. Allowing a caller to pass a custom timestamp parameter would allow rogue or desynchronized workers to prematurely revoke active leases or artificially delay expiry, violating Invariant I6.

### Q2. What makes 49 of 50 claims fail, and with which codes?

Answer (human): The first transaction acquires the lease, transitions Task.state to 'claimed', and writes a live HOLDS edge (closed_seq IS NULL, until_pt > now). The remaining 49 concurrent attempts fail because the antecedent guard conditions (Task.state = 'open', or the absence of a live HOLDS lease) are no longer satisfied. They return REJECTED_GUARD with the diagnostic probe name G3:task_open or G6:no_live_lease.

### Q3. Why does R4 take service and signature as params?

Answer (human): R4 (OpenIncident) uses p.signature as a deterministic deduplication key to prevent alert storms from opening multiple duplicate incidents for the same failure pattern. p.service binds the incident directly to the target system-graph entity to establish root impact edges and scope downstream coordination.

### Q4. How does R9 prove a citation is live?

Answer (human): R9 (PostUpdate) evaluates antecedent WHERE guards over cited facts matching (cs:Entity)-[cf]->() and verifies that cf.te = $INF (unclosed transaction interval) and that the valid time window covers the current transaction. If any cited fact was superseded by a newer version, the guard probe fails, preventing stale citations.

### Q5. Which guard probe is hardest to read?

Answer (human): ResolveIncident's root-cause verification probe (R11). Because FalkorDB bug S25 filters OPTIONAL MATCH variables before they are bound, the guard had to be refactored to compute root-cause cardinality within an aggregation rather than using a direct pattern filter, making the Cypher execution plan and probe predicate non-trivial.
