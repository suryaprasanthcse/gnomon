## Risky decisions

1. **PG checks are staged, not one WHERE.** Each Genesis validation is its own `WITH … WHERE` stage, and the UDF checks sit in `CASE`. A null `kernel_src` or `def_json` therefore filters the row instead of making `Kernel.sha256` throw. Every check still runs before the first write, in the §6.3 order. The guard probes mirror the stages, so diagnosis names the first failing one (`no_head`, `genesis_rule_pinned`, `kernel_sha_matches`, `has_agents`, `kernel_agent`, `agent_skills_known`, `rule_shas_match`).
2. **What `kernel_sha` pins.** It covers the UDF library, `composer.py` and the segment files, read with LF newlines. Any edit to `composer.py`, comments included, changes the sha, and a tenant bootstrapped earlier then holds a different `Head.kernel_sha`. Two further departures from the §6.6 text: Q0 digests `$view_keys` rather than `r.view_keys`, and test genesis runs in replay mode on the fixed clock (`pid` `genesis`). The first is the same value, read from the parameter. The second makes a copy bit-identical to a fresh bootstrap.
3. **Decisions the human took during the module.** D-9: package markers. D-10: PyYAML. D-11: the A00 smoke test now asserts the installed `genesis` fixture instead of the old placeholder error. One test-data typo of mine in `test_rule_sha` was fixed after RED: its "changed" `writes` value equalled the fixture's own. S23 holds throughout: aggregates come last in P0 and in every probe.
