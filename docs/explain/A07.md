## Built

The trust layer. It replays the log into a fresh graph from recorded inputs, hashes the whole logical graph canonically, runs audits K1–K6, and shows that every audit catches its Core mutations.

## Risky decisions

1. **I built to the runbook, not to the chat brief (D-27).** The brief named different files (`audit/{hash,invariants}.py`, `kernel/invariant_probe.py`) and defined K1–K6 differently (K1 = bitemporal, K2 = chain, …). `gate.py` reads SCOPE from the runbook, and contract C1 makes the spec win. Every concern in the brief is still checked, just under the spec's labels: overlap = K5b, chain = K1, lease = K5a, causal = K6. KeyVersion and Outbox state are covered by K4, which compares the whole graph.
2. **Audits stronger than the §12.3 text (D-29).**
   - K6's query cannot see a ghost Rewrite that nothing points to, so K6 also lists Rewrites with no seq.
   - K3 recomputes rule shas, but a forger can compute a valid sha (MU7 does this on purpose). So K3 also requires each Rule to have been written by the Genesis or RegisterRule rewrite at its `registered_seq`.
   - K5c and K5d avoid the S25 shape (a WHERE on an OPTIONAL MATCH).
3. **Another platform quirk (D-30).** An inline map that references a variable bound by an earlier MATCH (`MATCH (w:Rewrite {id: e.rw})`) fails with "Variable not found". WHY-entity therefore uses `WHERE w.id = e.rw`. This is recorded as an observation, not yet a FACTS spike.
4. **The state machine is small: 10 examples × 30 steps.** It does apply claims, completions, expiries, citations, receipts and root causes, and its teardown runs a full replay. Handoff and ResolveIncident rarely apply in random runs. Their transitions are covered by the A06 tests and the scenario.
5. **The stateful test was edited after its RED commit (D-30).** CompleteTask and Handoff can now act as the lease holder, and the run is longer. This makes the test stronger, not weaker, but the edit landed in the feat commit.
