## Risky decisions

1. **The rollback test's read was changed after RED (D-8, FACTS S23).** `RETURN h.seq, count(r), h.x` panics the pinned server (`reply_compact` unwrap on None) whenever a property follows an aggregate, and that took the shared container down mid-run. The rollback itself was always correct. The test now reads with two plain queries. Later modules must keep aggregates last in RETURN/WITH. There is no spike test for S23, because reproducing it kills the container.
2. **Choices the spec leaves open, made stricter.** HLC inputs must be non-negative integers no larger than INF. Integers beyond 2^53 - 1 arrive in JS as BigInt, so they are rejected rather than rounded. A lone surrogate becomes U+FFFD. Recorded modes never read `wall` or the message fields. `7` and `"7"` digest the same, because §8.2 encodes the decimal text, so field kinds must stay fixed per position.
3. **The sha is taken from the server, over LF text.** `library_sha` hashes what `WITHCODE` returns, and the loader sends the file read with universal newlines, so a CRLF checkout (git autocrlf on Windows) yields the same sha. The loader replaces a library only when its code differs, so parallel workers never `REPLACE` under traffic (S22). A concurrent first load that loses the race is accepted if the server ends up holding the same code.

## Questions

### Q1. Why 2^53−1 for INF?

Answer (human): JavaScript Number.MAX_SAFE_INTEGER is 2^53 - 1 (9007199254740991). Numbers above this lose 64-bit float precision and become BigInt, which FalkorDB/Redis serialization does not uniformly support.

### Q2. Why is the netstring encoding prefix-free, and why does that matter?

Answer (human): Length prefixes (<len>:<content>,) ensure no valid serialized token stream can be a valid prefix of another. This prevents cryptographic canonicalization collisions across variable-length string/integer tuples during SHA-256 digest computation.

### Q3. Walk through recv when the message pt equals the local pt.

Answer (human): When m.pt == local.pt, the outcome depends on the wall. If wall <= pt, physical time hasn't advanced past the local clock: output pt stays local.pt and lc_out = max(local.lc, m.lc) + 1. If wall > pt, the wall wins: pt_out = wall and lc_out = 0. If lc_out exceeds LC_MAX (1048575), recv throws LC_OVERFLOW.

### Q4. What happens to an apply query when tick throws?

Answer (human): FalkorDB executes GRAPH.QUERY mutations atomically. An uncaught UDF error triggers an immediate transaction abort and rollback (platform fact S4), leaving zero partial writes or orphan nodes.

### Q5. Why must replay never read the wall clock?

Answer (human): Replay must be strictly deterministic and bit-for-bit reproducible. Reading physical wall clock would generate new timestamps and corrupt the downstream cryptographic hash-chain digests (Rewrite.digest).
