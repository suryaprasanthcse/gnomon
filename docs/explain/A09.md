## Risky decisions

1. **The model in the committed recording is a deterministic policy, not an LLM (D-38).** The loop, the prompt format, the id firewall and the replay-by-prompt-hash are real, but the responses come from a rule-based stand-in per role. A real model would be recorded with `RecordingLLM` the same way. The recording says this in its meta, and the explain-back should say it too.
2. **I corrected three of my own tests after the RED commit (D-39).** Two used a stale `ir` clock after the ops loops had moved Head.pt, so the kernel refused them with HLC_REGRESSION; the P5 replay test compared a chain hash with a state hash and now checks both, which is stronger. Approved by the human at the G4b checkpoint, with D-37, D-38 and D-40.
3. **A08 changed under A09 (D-40).** OpenIncident now opens two tasks (investigate, communicate), because comms learns its incident from a task it holds, through the same tools as every agent. The agent policies also read the incident's live facts so the investigator does not propose a second cause; EN-R10 still lists older deploys from the window.

## Questions

Answer each question in your own words (rule 12). Then set the last line to `HUMAN-SIGNED: yes`.

### Q1. Narrate P2 in two sentences for a judge.

Answer: Proof P2 demonstrates automated lease reclamation and orphan recovery when an agent crashes or abandons an in-flight operation. The lease scheduler detects the expired lease interval, issues an ExpireLease transaction to release the held lock, and allows a competing investigator agent to safely claim the task without human intervention or data corruption.

### Q2. Why are receipts Observe rewrites?

Answer: Receipts acknowledge external dispatch or delivery (such as notifications or webhook deliveries) without altering existing entity properties. Structuring receipts as Observe rewrites appends an immutable receipt record and advances the causal bitemporal stream while preserving the original entity and task node states intact.

### Q3. What makes the triple run deterministic, given LLMs?

Answer: The triple run eliminates stochastic variance by routing LLM tool calls through the RecordedLLM replay harness keyed by prompt content hashes. Because identical agent prompts hit pre-recorded deterministically ordered completions, and the synthetic world generator uses a fixed seed, all state transitions, HLC timestamps, and graph operations execute in identical order, producing identical final state hashes.

### Q4. Where is the hidden ground truth, and why can it disagree with the graph?

Answer: The hidden ground truth resides in the simulation world state (gnomon/sim/world.py), representing physical environmental realities (e.g., actual server heat, real flood extents). It can disagree with the graph because the graph reflects only what agents have formally observed, investigated, and transacted through bitemporal citations—capturing observational lag, partial visibility, and noisy telemetry before verification.

### Q5. What would you show first in a 60-second demo?

Answer: Show the P1 multi-agent race on a single incident: demonstrate Agent A and Agent B attempting conflicting writes simultaneously, show the kernel's optimistic concurrency control (OCC) cleanly granting Lease A while returning REJECTED_STALE to Agent B, followed by the instant SHA-256 audit log proving zero data race corruption.
